## What the family update must demonstrate before release

- **Before installation:** confirm the exact installed app and signing certificate against the official, digest-pinned release for the box’s userspace ABI. A signer mismatch, a different starting build, or an unreadable signed-in profile stops the update. No private app data or backups are pulled.
- **After installation:** verify the installed 1.1.2 executable and original signer again, then verify the complete original server inventory in the stock picker. **Expected difference: family may need to re-select server/profile or sign in.** Never type their credentials. The local before-label file is for the owner only; shared receipts contain salted equality checks, not names or settings text.
- **After the synthetic playback:** restore and reopen the backend and options recorded in the lab profile before the harness changed them, remove only the uniquely titled lab server and verify the original inventory without selecting a family profile. Revoke the helper permission, remove the newly installed helper and verify both helper absence and removal of the synthetic screenrecord. Leave 1.1.2 installed. Never clear data, uninstall or downgrade to recover. Unverified cleanup remains visible; it is not a successful restore.
- **Owner restore:** while Wireless debugging is still enabled, use **Forget this PC under Paired devices** for the lab pairing (also forget an old personal-computer pairing if present), then turn Wireless debugging off. Only an explicit refusal at the exact supplied wireless endpoint verifies that port closed. A timeout, an open connection or the separately observed legacy listener is not equivalent.

The six-digit pairing code is entered privately when the harness prompts, never in a command, log or message. The harness uses a pinned, isolated ADB client labeled `cleanyfin@lab`; it never offers the personal default key. Each rehearsal uses a fresh key and a private AVD. The playback adapter, not the read-only probe, installs the verified APK and manages the synthetic recordings. Device loopback reaches only the synthetic server via an explicit reverse mapping into the private ADB namespace. The neutral-key pairing witness alone does not verify capture or preservation. Do not run the disposable fresh-install or HDMI procedure as a substitute. The separate HDMI path requires a real UVC/UAC signal: a capture-adapter logo, black/protected output or nominal capture resolution is not a measurement. No splitter or change to content protection is part of this test.
