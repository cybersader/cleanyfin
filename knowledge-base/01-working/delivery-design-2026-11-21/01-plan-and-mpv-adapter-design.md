# A filtered Jellyfin item that contains no edited movie

**PROPOSED · 2026-11-21 · design for a disposable first slice, not a household release.**

## Decision

Give the viewer a second **item**, not a second source on the original item. On Play, the plugin resolves the signed-in viewer's policy against the exact original, advertises its supported tracks and the **filtered** runtime, and hands an unmodified mpv client a text list of ranges to keep. Jellyfin still serves the original bytes. The shared service never receives a viewing session, a resolved plan or any media.

**Prove the handoff before building the library manager.** Can a real plugin, with neither a public media URL nor a probe impersonating a player, hand one authorized Wholphin session its two URLs? Make the bare pointer unplayable; restart, refresh and play it again. If that requires an administrator's key, changing the client, handing out a reusable Jellyfin token, patching the server, or sometimes returning the original under the filtered identity, **reject this mechanism**. A successful handoff is permission to measure presentation, not to label it safe.

## What the lab actually established

**MEASURED** ([Wholphin, both experiments](../client-ecosystem-2026-11-21/google-tv-clients.md#hands-on-test-2026-11-21-wholphin-v112-and-a-strm-pointing-at-an-mpv-edl)). A `.strm` item with no streams made Wholphin 1.1.2 select Transcode; the server returned 500 and the cut list never played. Serving MP4 to the probe and EDL to the client under the same URL produced a 20 s H.264/AAC description. Wholphin chose DirectPlay; libmpv fetched the list then the original with `Range: bytes=0-` (206). The player clock and reported position followed about **14.96 s**, not 20 s. No marked picture was detected; control showed the mark. Nine neighbouring frames were unreadable in *both* runs. No Android audio or persisted resume evidence. This is a Google TV emulator with particular rendering settings, not the household TV. Do not copy the user-agent switch.

**MEASURED** ([cross-path results](../playback-paths-2026-11-21/README.md#first-measurements-2026-11-21-shared-hard-fixture-cut-inside-a-gop-and-inside-an-aac-packet)). Desktop mpv preserved all 374 kept frames, omitted all 126 marked frames and had no detected marked tone, but **448 PCM frames differed** after the splice. Kodi showed marked frame 255. Media3 clip transitions lost kept frames and audio; stock Android TV played the progressive edited MP4 test but not its muxed HLS playlist. These are different mechanisms, not transferable approvals. PlaybackInfo's “supports” flags were not playback measurements.

## Plan v1: an instruction, not a lookup result

**Ownership.** The Go API stays a source of timestamp metadata. The **household plugin** reads an accepted snapshot, verifies the asset, applies private policy for the authenticated Jellyfin viewer, and produces the plan. A shared host cannot do that without learning household choices and trusting someone else's file identity. A household-local Go resolver could implement the same contract later; do not split processes or duplicate decision logic now. The mpv renderer receives a *resolved* plan, never raw crowd rows or a category rulebook.

**From existing inputs.** [Today's provider](../../../plugin/CleanyfinSegmentProvider.cs) queries `?fp=osh:…` or `jf:…` and maps milliseconds to ticks. [Moviehash](../../../plugin/Moviehash.cs) samples file ends. Neither OSHash + duration nor a local UUID proves the marks describe this edition. Locate candidates using the prefix route (or a local snapshot); bind the *reviewed marks* to the exact SHA-256 of the full source, length, selected Jellyfin item/source and reviewed track clock map. Hashing a new file after fetching marks for an unverified cut does **not** bind those marks. Start with a locally reviewed manifest for the single fixture; no automatic approval of legacy/pending rows. Later persist accepted annotation ID **and content digest** per origin/binding revision; never carry approval across mutation, disappearance/reappearance or a different encode without review.

**Resolver rule, slice 1.** Authenticate viewer → find configured private profile → load active policy and accepted local snapshot as one consistent read → verify coverage declaration, binding, streams and duration → apply explicit category/severity rules to accepted marks. Within that policy, a requested omission becomes `cut` (`skip` is an input spelling). A descriptive `mark` is not itself a filter. An intentionally unselected category is not an unknown action; a *required* mute, unknown type, exception of ambiguous authority, conflict the resolver can't resolve, no match, all-cut, zero actionable marks or a failed fetch without a current accepted snapshot gives **no offer**. Do not silently downgrade. Merge overlapping/touching cuts, preserving the contributing references, then sort. Preserve other spans exactly. Later explicit substitutions belong to a new household policy revision, never a renderer default. Slice 1 has no bypass workflow, ranking service or curator trust engine.

**Clock.** Keep existing integer **milliseconds on the uncut source presentation timeline**, intervals `[startMs,endMs)`, measured duration on that same clock. Not wall time, raw packet DTS, edited time, frame count divided by nominal fps, or a Jellyfin seek tick. V1 supports only boundaries representable at its stated precision; closed or approximate boundaries are rejected, not rounded out for safety. The verified binding names the timeline origin (presentation zero after container edits/delay compensation) and a per-track PTS anchor/timebase. Map using exact rational arithmetic: `source_time = anchorSourceMs/1000 + (PTS − anchorPts) × timeBase`. Use presentation timestamps, not decode order; account for edit lists, priming and decoder discard before comparing PCM. A track that starts later can have a nonzero anchorSourceMs. Reject discontinuities, unverified non-linear mappings, unrepresentable boundary requirements and incompatible track selections. Browser lab: 3.200 s nominal became **3.221406 s muxed**; hard-coding that difference into every EDL would be as wrong as ignoring it. Prove the mapping from source zero to the *player's* start clock for each tuple; for the first mpv fixture require verified identity, deny other origins until calibrated. Keep full tick/timebase precision in evidence even when input marks are ms.

**Schema outline to freeze in the first worker:** a draft-2020-12 `$id` under the project's versioned namespace, `type: object`; require every field shown. All semantic objects closed (`additionalProperties: false`); a single optional `extensions` object at root is **descriptive only**, size-bounded and ignorable. Reject unknown fields anywhere else, unknown major versions, required features or actions, duplicate keys and duplicate references. `planVersion: const 1`; `requires` unique feature strings, contains every operation's required feature; v1 cut-only reader accepts only `cut`. A future v1-compatible reader can explicitly support additional required features; writers must never hide changed semantics in `extensions`. Otherwise use a new plan version. Integer values exact in JSON-safe range; duration/size positive, timebase positive integer pair, signed PTS anchor; nonempty capped strings/arrays and valid 64 lowercase hex digests. UTC timestamps strictly parsed; a checked clock and `issuedAt ≤ now < expiresAt` required. Proposed implementation limits: 1 MiB plan, 4,096 operations, 8,192 input refs; reject before allocating unbounded work. Validate unique track indices, references, accepted input digests, complete binding, sorted non-overlap and `0 ≤ start < end ≤ duration`; checked conversion to Jellyfin ticks (`ms × 10,000`). Reject invalid input, don't clip to fit. Metadata-only extensions can't add a source URL or executable option.

A locally allocated non-reused revision names immutable plan bytes. Issue/renew as a new revision; do not use an item's mtime as policy freshness. Maintain a separate stable **timeline key** derived from source/binding, track set and normalized cuts (not renewable ticket/expiry) for a resume record. Bump/change active generation on source, policy, trust or annotation change. Verify exact source identity when indexing and serving: for the lab use an immutable, read-only fixture; bind a pinned single local source, not “first source”. In production a pathname + cached hash/mtime is not proof against same-path replacement. Require a stable asset version/immutable snapshot or a verified open-file identity held through serving; until demonstrated with Jellyfin's own static reader, mutable/racing originals are outside the offer. Re-hashing a large movie per range is not a scaling strategy.

### Render and map once

For duration `D`, take the complement of the normalized cuts in `[0,D)`. `filteredDuration = Σ kept lengths`. Each kept interval has a filtered start equal to the sum of the preceding lengths. Within a kept interval translate by that offset; at the filtered splice choose the **start of the next kept interval**. A source seek inside a cut maps to that splice, or filtered end if there is no suffix. No zero-length entries. Example (tokens below are placeholders):

```text
# mpv EDL v0
https://jellyfin.example/Cleanyfin/play/S/source?t=B,0.000,5.480
https://jellyfin.example/Cleanyfin/play/S/source?t=B,10.520,9.480
```

The splice is at 5.480 filtered seconds; 7.000 filtered seconds means 12.040 source seconds (frame 301 at 25 fps). Generate fixed decimal seconds, invariant locale; use mpv's `%<UTF-8-byte-count>%<value>` quoting for URLs, not CSV quoting. Build URLs from trusted configured origin and generated identifiers only; reject control characters, fragments, other hosts, user-provided paths, schemes and redirects. No `edl://` inline in a `.strm`, no options/scripts from data, no remote→local reads or relaxed mpv safety setting. `!no_chapters` is available for suppressing automatic EDL/source chapters; verify it or reject files with chapters and suppress previews in slice 1. The renderer cannot make a mute by deleting the picture too.

**Proposed first handoff:**

1. In a disposable Jellyfin, create a plugin-owned shelf directory, outside movie paths. One `.strm` contains only an absolute same-origin URL such as `/Cleanyfin/pointer/{opaque-id}` with configured scheme, base path and host. This inert locator **never** returns media, a plan, redirect, or ticket (404/410 even for probes). No client identification by User-Agent, no credentials on disk. Give only enrolled viewers shelf access; map pointer → selected original item/source and profile locally. Catalogue only sanitized title and filtered runtime for that profile/timeline; distinct item per differing timeline/profile if necessary. No external metadata/automatic identification, merging, artwork, previews or library writeback. Add/delete only owned files via atomic rename; reconcile on startup and refresh. On removal the plugin can leave dead pointers, never playable originals.
2. Supply stream info by copying **data fields**, not the entire original `MediaSourceInfo`: index/type, codec, profile/level, resolution, frame rate, bitrate, sample rate, channels/layout and tested defaults from the bound source. No original path, alternate URLs/IDs, subtitles, attachments, external stream URL, segments, or copied chapters. Reject an unsupported physical track instead of merely hiding it in the DTO: mpv opens the actual file. Use `Container=mp4` as the decoder capability description of the underlying tracks; the **HTTP descriptor itself is text**. Separate metadata projection from format negotiation. `RunTimeTicks=149600000`, not the source's `200000000` for the example. Set browse runtime on pointer and playback runtime on source consistently. For browsing, if needed use `SaveMediaStreams(pointerId, copies, ct)` and the item update API, never direct DB writes. Reconcile only changed owned projections, avoid self-triggering update loops; if refresh can expose the wrong track/runtime or rescan cost is unbounded, do not publish the shelf.
3. Register a version-pinned MVC action filter via the plugin registrator. No competing route: intercept **only** GET/POST PlaybackInfo for positively identified generated items, after native authentication/authorization, before shortcut reprobe. For normal items execute core unchanged. An orphan pointer always points to the inert URL; never infer its binding by parsing its filename. For generated GET with no sufficient capability context return no playable source. For POST validate the actual session (no arbitrary body/query user override), source choice, original/shelf access, playback permission, policy, profile, device, version, backend, direct-play request, bitrate/codec/track constraints and current plan. Respect Jellyfin restrictions; no forcing DirectPlay when native device negotiation, requested delivery or access would forbid it. Use pinned ordinary source/profile evaluation on the **original**, not the `.strm`; reject any required remux/transcode or non-unique local-file result. Do not call PlaybackInfo recursively. If this cannot preserve native restrictions, stop. In particular don't override a failed core access check by looking up a raw ID.
4. Produce the normal `PlaybackInfoResponse` shape: fresh play-session ID, exactly one source with **pointer source ID**, whitelisted media info, `Protocol=Http`, `IsRemote=true`, eligible `SupportsDirectPlay=true`, `SupportsDirectStream=false`, `SupportsTranscoding=false`, no transcoding URL, no opening requirement. Its `Path` is the externally reachable *descriptor* URL with a session capability. No media bytes handled. For denial return a normal error/no-compatible-stream and no sources; a naked pointer, direct-stream retry, open-live request, disabling the plugin or attempting a generic transcode of the pointer cannot lead to original bytes. Check downloads, trailered extras, autoplay, resume and previews separately; turn off any unproved route. If stale item DTOs still show a tile, the shelf/title must not promise a supported filtered option; leave neutral request-only lab titles until eligibility can be represented, and block on Play regardless.
5. State the access boundary. Library ACLs can partition **policy shelves**; authorize both pointer and exact original for this slice. Two signed-in profiles can resolve different plans and see different shelves. A viewer who already has ordinary source access can deliberately play the original in its own library: no filtered-label fallback, **not** parental lockout. A profile denied the original gets **no grant** even if it sees the pointer. Never secretly elevate to make a hidden original work. A filtered-only principal would need a distinct audited derivation right and tests of all bypasses, a later product decision. A global `.strm` is not an ACL or an authenticated identity.

**Single falsifier:** real plugin + inert pointer + original fixture + unmodified Wholphin/MPV on the same disposable 10.11.11 lab. Trace redacted native auth/PlaybackInfo → exactly one session URL → descriptor GET → native static original 206. Withhold plugin stream projection (negative control), switch Wholphin to Exo, deny original access, expire/revoke ticket, refresh, restart, corrupt plan and disable plugin. Require at least the positive path to play, **zero original fallback or transcoder media output under the pointer** in any run, nonmember denial, and normal original PlaybackInfo unaffected. Compare original and two profile runtimes/bookmarks. A positive requiring special ffprobe content, an ambient leaked credential or a persistent global hook that cannot be scoped falsifies the choice; don't paper over it with a prebuilt edited MP4.

## HTTP and authorization: the cut list and the bytes are different authorities

```text
Wholphin --native authenticated POST PlaybackInfo(pointer)--> Jellyfin + plugin gate
        <-- remote Path: /Cleanyfin/play/S/list.edl?t=A --------
libmpv   --GET that path-------------------------------------> EDL text
         --GET /Cleanyfin/play/S/source?t=B, Range: bytes=...-> narrow admission
              same request, fixed native static original route -> original bytes from Jellyfin
```

**Proposed minimal contract:** viewer auth at issuance; scoped bearer credentials at consumption. Already authenticated Wholphin SDK requests are not evidence of libmpv headers/cookies on the list or nested file. The EDL must be directly usable as a URL; nested entries each carry **their own** B, not a URL relative to A that hopes a query/header will propagate. Generate high-entropy opaque random handles (≥128 bits) from a CSPRNG; store hashes in a bounded in-memory session table, expire by server clock. Scope A to list, B to original static bytes only, bind each to server/session/principal/device enrollment, pointer, original/source/digest, plan revision, purpose, allowed methods and expiry. A bearer can be replayed within that grant if stolen; binding records who authorized it, **not** proof of caller possession of that device. TLS for any non-loopback hop; trusted configured public origin and Jellyfin base path, not request Host. No redirects, cookies as the only mechanism, cross-origin requests, public plans or CDN.

| Resource / alternative | Behavior |
|---|---|
| Native POST; optional local plan inspection | SDK uses normal Jellyfin authentication. No public plan endpoint needed; if diagnostics later expose JSON, require the matching current principal or explicit admin role. List and JSON have distinct URLs. Return `406` for explicitly incompatible `Accept`, allow `*/*`; if negotiation at one URI is added, `Vary: Accept`. Never choose original vs EDL by Accept or agent. |
| `GET` / `HEAD .../list.edl?t=A` | Check ticket **before** cache validation. Stable per-grant bytes, `text/plain; charset=utf-8`, content length, `Cache-Control: private, no-store`, no referrer. Optional strong ETag from plan revision, adapter revision **and representation bytes** (which include B); not plan ID alone. HEAD same headers, no body. A small EDL may ignore Range and return complete 200; never a media `206`. Bad credential 401/403 or generic 404; inactive known session 410, unsupported 409/no-compatible-stream; no playable error body. |
| `GET` / `HEAD .../source?t=B` | Authorize current session and source before *each* request, including ranges and conditional requests. Recommend **internal delegation to Jellyfin's exact static original route**, not opening/copying media in plugin code: `[GET/HEAD] /Videos/{originalId}/stream?static=true&mediaSourceId={boundId}`. [Pinned controller](https://github.com/jellyfin/jellyfin/blob/1fbd8739292cce610231be93daf43368733edf63/Jellyfin.Api/Controllers/VideosController.cs#L442-L484), [native file result enables ranges](https://github.com/jellyfin/jellyfin/blob/1fbd8739292cce610231be93daf43368733edf63/Jellyfin.Api/Helpers/FileStreamResponseHelpers.cs#L103-L110). Only a single local immutable file, not remote, live, multi-version or direct-stream provider. Normal full 200 or valid byte 206/`Content-Range`; unsatisfiable 416, accurate HEAD/length; preserve `Range`/`If-Range`. Byte offsets are into the **whole original**, not kept media. The original's validator describes bytes; don't reuse the plan ETag. Override public caching on this ticketed path to private/no-store. |
| Hand the player `/Videos/...?...&api_key=...` | **Reject** despite convenience. [AuthorizationContext](https://github.com/jellyfin/jellyfin/blob/1fbd8739292cce610231be93daf43368733edf63/Jellyfin.Server.Implementations/Security/AuthorizationContext.cs#L82-L117) reads `ApiKey` and, when legacy auth is enabled, `api_key`. A normal user login token or server API key is not item/purpose-limited. It leaks to request logs, copied URLs, player diagnostics and caches. A redirect to a credential-bearing native URL has the same problem. |
| Short-lived stateless signed URLs vs opaque handles | A MAC covering purpose, exact item/viewer/revision and expiry can work; replay, revocation lists, log exposure and key rotation remain. **Use ephemeral server-side handles first**: one household, cheap invalidation on logout, policy change or restart, no signing infrastructure. Never embed credentials in scan results, `.strm`, shared data or plan. No bootstrap from an unauthenticated pointer GET. |
| Plugin byte-serving controller / reverse proxy | `PhysicalFile` with ranges is technically possible, but makes the plugin a file server with path, range, ACL and identity responsibilities; a loopback fetch-and-copy is a media proxy. **Neither is the default** under the metadata-only rule. A required external reverse proxy would also worsen installation. |

**How to test the internal delegation without inventing a universal token.** First record (presence only, not values) whether native user auth survives either GET; don't require it. A proposed in-process adapter registered through DI as an ASP.NET Core `IStartupFilter` handles only the plugin's exact `/play/{S}/source` GET/HEAD before native authentication/routing ([host pipeline at this pin](https://github.com/jellyfin/jellyfin/blob/1fbd8739292cce610231be93daf43368733edf63/Jellyfin.Server/Startup.cs#L149-L216)). Validate B and all current bindings, use the authenticated **non-admin viewer's own** live session from issuance, fail if revoked, and internally set the normalized native authorization header for this request only. Keep the native session credential/reference memory-only for its shortest needed lifetime; no service account, URL token forwarding, access to another viewer's session or fabricated principal. Replace the target with a fixed route/allowlisted query derived solely from the binding; do not proxy over HTTP, re-enter from a caller-supplied path, or carry caller auth/query overrides. Respect base paths, native account restrictions and response headers; only bytes on this connection come from the native static-file result. No general-purpose exchange endpoint. A plugin A/B ticket is **not** something stock Jellyfin knows how to authenticate. Prove service registration order, header interpretation, no redirect and no buffering in the actual host; the source links do not prove any of those. If impossible without weakening core auth or touching media, the proposed handoff fails. Prefer an upstream item-scoped native grant if a later pinned version provides one.

Validate both item ACLs, playback permission, user/session active, source identity, current revision and evidence at issuance and each grant use. If the request contains an independently authenticated conflicting viewer, deny. Disable URL logging including query **and capability-bearing paths** at the app, proxy and lab trace; examine playback history, debug logs, crash/telemetry and saved paths using disposable sentinel credentials before promotion. Only route templates, status, durations and reason codes for routine diagnostics. Set no-store on ticket-bearing PlaybackInfo too. Rate/size/concurrency caps; expire idle grants, refresh only through newly authenticated playback. Fixed absolute expiry no later than plan expiry; choose a ceiling covering the supported feature length plus margin, otherwise refuse before start (lab: 20 s clip, 30 min max). A pause past expiry means restart with a new authorized offer, not fallback. Cache locally accepted *metadata* only while revision/trust/expiry checks still pass. Invalidate all grant handles on new policy, source, revocation, user logout, rollback/uncertain time or plugin restart. Known revocation outranks unexpired cache. Cancel outstanding requests best effort. Bytes already downloaded, a cached EDL or an already-buffered presentation **cannot be recalled**; fresh requests stop, not an instant remote kill switch. If immediate mid-session enforcement is required, this is the wrong delivery model.

### Test layers and acceptance

1. **Pure CI (no media server, no network).** Freeze a v1 schema, JSON golden inputs, explicit `no-offer(reason)` and expected EDL bytes/time mappings. 3. **End-to-end evidence.** Use the existing [hard fixture and scorer](../../../tools/playback-lab/README.md#shared-hard-fixture-compare-playback-paths): 20 s, 25 fps, mid-GOP B-frames, cut source `[137,263)`, AAC mid-packet, distinguishable neighbours and tones. First capture unfiltered control **at the same output point**: all expected 500 frame identities and known tones. Then capture filtered straight play, repeated forward/back seeks, pause at join, persisted stop/resume on either side and at seam, a second cut and EOF. Score presented output against the expected itinerary (split/rebase captures for intentionally backward seeks; scorer flags backward jumps in a straight run). Need **all 374 kept and no marked** on the single straight cut; specifically witness 136→263. Repeats/drops and splice stall recorded separately. A 15 fps recording cannot prove a 25 fps sequence. Use presentation-layer capture on a sound-enabled emulator that can distinguish every frame, not decoder-submitted frames alone. If unavailable, row stays partial.
4. **Android audio is a gate, not a checkbox.** Headless `-no-audio` and unsuccessful `ao=pcm` are not evidence. Capture actual mixed/rendered PCM in a sound-enabled synthetic run without changing the Wholphin binary; identify sample rate/channels, compare control, align **once** for capture latency, then compare each side against decoded original prefix/suffix. No re-aligning the suffix to conceal loss. Score the existing 5 ms tone windows **and** sample counts, neighbouring waveform/energy, insertions/deletions and both channels; use a known transient/sample witness if needed to distinguish kept material from AAC ringing. Report capture resolution/noise floor and remaining detection limit. Any observed marked presentation fails; unexplained kept loss/alteration or inadequate instrumentation is not a pass. Calibrate the capture against uncut control; if the rig cannot resolve the claim, leave it unproved rather than inventing a tolerance. Lab video/PCM captures are synthetic test artifacts, not product outputs. Then run Streamyfin independently and log a stock-app refusal. Physical TV/receiver tests require separate authorization; emulator success is never a household hardware result.
