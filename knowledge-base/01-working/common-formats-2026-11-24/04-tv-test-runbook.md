**No command is released for the household box until the combined rehearsal passes.** The [signed-in emulator rehearsal](../../../delivery/evidence/runs/tv-20261126T062510Z-327a0f1ff3/summary.json) actually updated Wholphin from 1.0.9 (code 60) to 1.1.2 (code 63), in place. Before installation, the harness verified the public APK signer, original server list, active server and user, MPV backend and saved options. After installation, the verified new app opened **Select Server**, not authenticated Home. The synthetic server was still visible. That does not establish that sign-in was lost, but it does **not** prove that the original active profile and settings survived. The harness stopped before adding a lab server or playing media. The expected version was the only manifest change; private rig cleanup succeeded. No clear, reinstall, downgrade or reauthentication was attempted.

**Capture route:** the earlier mpv WAV route replaces speaker output and is blocked; do not try storage workarounds. A separate [emulator-only playback-capture rehearsal](../../../delivery/evidence/runs/tv-20261126T052912Z-2768710d30/summary.json) did capture Wholphin's ordinary, synthetic AudioTrack playback and verify helper/grant cleanup. It returned stereo with signed-16-grid values, not the original six channels. It is not a bit-exact tap or a rehearsal of jointly capturing audio and screenrecord on the family box. The intended TV evidence is marked-signature detection in audio, gap-bounded frame IDs from screenrecord, and separate seam observations calibrated against an uncut control on the same device. Neither emulator timing nor camera/screenrecord gaps prove physical HDMI output. See the [measured limits and TV contract](../testing-approaches.md#what-tv-r24-should-measure-instead).

**The family accepts possible re-sign-in.** The new gate is retention of the original server entries, not automatic authenticated Home. The owner still needs evidence of the signed update, lab-only cleanup and fresh concurrent capture for the intended procedure. The historical signed upgrade and audio-only receipts do not establish that. Do not substitute a desktop result, a successful APK install or a private emulator's audio timing for either gate.

The owner’s read-only probe identified `jarvis2`, Android 14 / SDK 34 (2026-06-01 patch), Amlogic S905X5M but **32-bit userspace**. Its ABI list selects `armeabi-v7a`. The display reported 3840×2160 at 59.94 Hz (mode 152; 1080p available). A 1280×720 screenrecord worked, but a static screen produced one frame: nominal Hz is not recording cadence. Jellyfin Android TV 0.20.0 is not the tested player. HDMI surround was `1`; both frame-rate-match settings were unset. A separate legacy ADB listener was observed on 5555. The harness never connects to it: verifying the supplied wireless endpoint closed does not prove legacy ADB closed.

## What the family update must demonstrate before release

- **Before installation:** confirm the exact installed app and signing certificate against the official, digest-pinned release for the box’s userspace ABI. A signer mismatch, a different starting build, or an unreadable signed-in profile stops the update. No private app data or backups are pulled.
- **After installation:** verify the installed 1.1.2 executable and original signer again, then verify the complete original server inventory in the stock picker. **Expected difference: family may need to re-select server/profile or sign in.** Never type their credentials. The local before-label file is for the owner only; shared receipts contain salted equality checks, not names or settings text.
- **After the synthetic playback:** restore and reopen the backend and options recorded in the lab profile before the harness changed them, remove only the uniquely titled lab server and verify the original inventory without selecting a family profile. Revoke the helper permission, remove the newly installed helper and verify both helper absence and removal of the synthetic screenrecord. Leave 1.1.2 installed. Never clear data, uninstall or downgrade to recover. Unverified cleanup remains visible; it is not a successful restore.
- **Owner restore:** while Wireless debugging is still enabled, use **Forget this PC under Paired devices** for the lab pairing (also forget an old personal-computer pairing if present), then turn Wireless debugging off. Only an explicit refusal at the exact supplied wireless endpoint verifies that port closed. A timeout, an open connection or the separately observed legacy listener is not equivalent.

The six-digit pairing code is entered privately when the harness prompts, never in a command, log or message. The harness uses a pinned, isolated ADB client labeled `cleanyfin@lab`; it never offers the personal default key. Each rehearsal uses a fresh key and a private AVD. The playback adapter, not the read-only probe, installs the verified APK and manages the synthetic recordings. Device loopback reaches only the synthetic server via an explicit reverse mapping into the private ADB namespace. The neutral-key pairing witness alone does not verify capture or preservation. Do not run the disposable fresh-install or HDMI procedure as a substitute. The separate HDMI path requires a real UVC/UAC signal: a capture-adapter logo, black/protected output or nominal capture resolution is not a measurement. No splitter or change to content protection is part of this test.
