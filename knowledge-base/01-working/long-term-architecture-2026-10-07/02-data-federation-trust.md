Verdict: evolve toward household-local SQLite, private policy overlays, and explicitly trusted curator snapshots—not shared-row multi-writer federation. The current API is a useful prototype, but its visible-only dump is neither a recoverable backup nor a replication protocol. Pending submissions are already public, submitter IDs are unauthenticated claims, duration is not part of lookup identity, and the plugin uses exact fingerprint requests without timeline validation.

The immediate decision is whether correctness and local autonomy take precedence over automatically maximizing coverage. Recommended strategy: preserve uncertain matches as unverified, separate community assertions from household decisions, implement versioned snapshot import/export with atomic replacement of one publisher’s public namespace, then add signed distribution when independent mirrors are introduced. Add deltas or multi-writer exchange only after measured needs justify them.

Owner decisions remain explicit: what happens when filtering data is missing or stale; whether unreviewed legacy records stay publicly usable; backup/outbox data-loss tolerance; and whether public contribution linkage is acceptable. None is established by the existing code or license declarations.

Evidence is source inspection plus bounded synthetic/SQLite checks, not live Jellyfin compatibility or production resilience. Existing Go tests could not run because Go is absent. External access occurred on 2026-10-08 for the requested 2026-10-07 research workstream.

1. IMPLEMENTED versus promised architecture. At HEAD 2426cef1ab345a5a829b2ce7a6fe8fab8661011e, persistence is a flattened segment table plus vote table, with no work/edition entities, curator ownership, private scope, correction log, tombstones, or import cursor: server/internal/store/store.go:41-65. InsertSegment assigns a random ID and pending status, but exact lookup, prefix lookup, and dump all admit anything except hidden or votes ≤ −2: same file:139-184,201-222. Thus pending is not a moderation barrier; the predicate would also expose auto_suggested rows, although the present submission route always creates pending. The public routes contain no write authentication, and caller-supplied submitterId is accepted directly: server/internal/api/api.go:35-47,180-225,234-249. Two invented identities can supply two downvotes; one actor can also impersonate an existing voting identity. Vote replacement is transactionally implemented, but one string is not one person: server/internal/store/store.go:225-255. Documentation describing queues, curator locks, and privacy guarantees is not implementation evidence.

2. PROPOSED entity and trust-boundary model. Separate (a) Work: origin-qualified ID and provenance-bearing external aliases; (b) Edition/Timeline: a particular cut, duration, timestamp origin, and relevant audio-track/language identity; (c) Asset: byte-level representation, size, optional cryptographic digest, OSHash locator, and observed duration; (d) TimelineBinding: asset-to-timeline mapping, anchors, method, residual error, reviewer, confidence state, and revision; (e) Annotation: stable origin-qualified ID with immutable revisions, span, taxonomy version, creator claim, generation method, license evidence, and supersession links; (f) CurationDecision: a named authority’s acceptance, rejection, classification, or corrected boundaries; (g) HouseholdPolicy: private subscriptions, per-viewer rules, and scoped per-movie exceptions with expiry. These are conceptual boundaries, not a requirement for seven services. Keep them in one SQLite application. Local file paths, Jellyfin user/item mappings, exception requests, and viewing history stay household-private. An upstream publisher owns its assertions, never the household policy. A mirror transports bytes, never acquires authority merely by hosting them. External title identifiers are aliases, not globally infallible identity.

3. SOURCE-VERIFIED matching gap; PROPOSED correction. The actual fingerprint is osh:<checksum>, or jf:<itemId> fallback—not checksum plus duration: plugin/Moviehash.cs:22-34. The provider requests only that string and converts every returned span without checking duration, matching confidence, or calibration: plugin/CleanyfinSegmentProvider.cs:54-81. The API validates ordering but not positive duration or endMs ≤ durationMs: server/internal/api/api.go:197-218. OSHash samples file ends and is explicitly noncryptographic [S3]; even equal duration and size do not establish edition equivalence. Treat it as a candidate locator. A strong asset digest can identify bytes, but cannot itself map a different encode to the same timeline. Namespace jf fallbacks locally and never promote them as portable release identity. Retain integer milliseconds and half-open spans [start,end); validate bounded arithmetic before ×10000 conversion. Unknown duration means unresolved, not zero-length verified media. Approve constant offsets only after multiple distributed anchors agree; drift requires a separately verified rational-rate mapping, and edits require bounded piecewise mappings. Never extrapolate across unverified cuts. Chromaprint promises near-identical-audio matching, not arbitrary film-edit alignment [S4].

4. PROPOSED evolution and growth triggers. First, strengthen one household node: explicit publication states, private overlays, provenance, migrations, idempotent outbox, and real backup/restore. Second, add manual versioned snapshot export/import and local read-only querying; this already permits offline reads and community forks. Third, enable independently selected curator feeds and verified mirrors, retaining a single writer per authority namespace. Fourth, introduce deltas when measured full-snapshot download time, memory, or refresh windows fail the smallest supported installation’s declared budget. Consider multi-writer exchange only when independent communities demonstrably need to publish during partitions; exchange origin-owned assertions and proposals, not concurrent overwrites of one shared row. Database replacement should follow measured contention and operational requirements, not a borrowed project’s traffic level. REJECTED for the present requirements: CRDTs, blockchain, forced central accounts, ActivityPub/Matrix/Nostr infrastructure, and Git as a mandatory runtime dependency. A durable outbox with unique submission IDs does not require a CRDT; signed immutable files may be hosted through ordinary HTTPS, local files, or optionally Git.

5. PROPOSED provenance, identity, correction, and abuse controls. Bind writes to a locally issued pseudonymous capability or installation key; do not interpret display handles or hashed public IDs as credentials. An account-free interface can still authenticate possession. Keys establish continuity, not humanity: Sybils remain cheap. New remote submissions enter quarantine; verified curators publish independently of raw vote totals. Rate-limit by credential and cautiously by network, bound payload/storage consumption, retain minimal private abuse telemetry, and never let two unauthenticated negatives remove household-approved data. Scope reputation and vote totals to their originating authority; summing mirrored aggregates double-counts them. Use stable annotation IDs plus monotonically increasing origin revisions. A correction creates a revision; competing curators retain separate judgments rather than last-writer-wins. Deletion creates an origin-authorized tombstone; unpublishing is distinct from erasure and must not promise removal from old public copies. Record original source, acquisition date, license/version or consent evidence, automation method, reviewer, and transformations. Keep copied subtitle text and identifying media out of provenance by default. Existing legacy records lack evidence of authenticated authorship or CC0 assent; migration must not fabricate either.

6. PROPOSED snapshot and replication contract. Today's dump returns generatedAtUnix, count, and visible segments with aggregate votes; it omits hidden records and individual vote state: server/internal/api/api.go:163-177; server/internal/store/store.go:201-222. It cannot restore moderation or explain why a row disappeared. Define a separate public snapshot manifest with format major/minor, publisher ID, epoch, sequence, complete scope, creation/expiry times, license, record count, and exact payload lengths/digests. Import into staging, verify fully, then atomically replace only that publisher’s materialized public scope. Absence removes a previously imported row only from an authenticated complete snapshot of the same scope; never infer global deletion from a partial response. Household overlays survive replacement. A later delta declares base snapshot/hash, sequence range, unique event IDs, revisions and tombstones. Replays are deduplicated transactionally; gaps or base mismatch require a fresh snapshot. One-origin forks/equivocation are quarantined, not arbitrarily merged. Maintain tombstones until consumers must rebootstrap from an authoritative snapshot. A full private backup separately retains votes, audit state, outbox, policy, cursors, and required recovery material.

7. PROPOSED authenticity, key lifecycle, and malicious-mirror handling. Sign a small manifest binding exact payload bytes and interpretation-critical metadata; raw payload digests avoid dependence on incidental record formatting. If JSON objects themselves are signed, use a specified canonicalization such as RFC8785, not language-default serialization [S6]. Bootstrap publisher trust out of band; never accept a mirror-supplied replacement key merely because its signature verifies. For a small manually operated system, explicit operator re-pinning plus documented recovery is simpler than implementing unattended root governance. If unattended rotation/delegation becomes necessary, evaluate a maintained TUF implementation: specification 1.0.36 separates authorized signatures, version history, expiry, root rotation, and consistent snapshots [S2]. Persist highest accepted epoch/sequence and digest; reject rollback and conflicting content at an accepted version. Define rotation/revocation and compromised-root recovery before automatic updates. A valid signature proves authorized bytes, not safe timestamps, honest curation, completeness, or freshness. Mirrors can still withhold updates; expiry and clock checks can detect some staleness but cannot deliver missing data. Disconnected clients cannot learn fresh revocations. Offline last-known-good use must expose age and the chosen policy, not masquerade as current verification.

8. PROPOSED local trust and privacy. Resolve local explicit exceptions first, then the household’s ordered subscribed curators, then optionally community suggestions. Preserve disagreements and show why an interval applies; neither global vote totals nor curator locks should override local authority. An exception must be scoped to work/edition, audience, categories/actions, and expiry so a movie-level permission does not silently become a library-wide bypass. Hash-prefix requests reduce query specificity but promise no minimum anonymity set. The server accepts 4–16 hexadecimal characters and returns complete matching fingerprints: server/internal/api/api.go:128-160. The plugin currently uses exact lookup instead: plugin/CleanyfinSegmentProvider.cs:58-59. Public fingerprints need not directly name a movie, yet joinable title mappings and submission history permit linkage. Stable submitterId is public in segment/dump records; the PWA sends a typed handle or 'anonymous': server/internal/store/store.go:26-38; pwa/src/main.ts:120-136. Prefer local snapshots and scheduled broad feed retrieval to per-play remote requests. Per-community pseudonyms reduce cross-community linkage; do not publish IPs, local IDs, household policies, or viewing events. Signing every user action globally would increase linkability and is unnecessary for initial curated snapshots.

9. PROPOSED backwards-compatible API and migrations. Preserve v1 wire fields and legacy IDs through an origin-qualified mapping, but do not claim that retaining permissive behavior preserves safety. Add a versioned read contract expressing resolved asset/timeline, publication state, provenance, confidence, coverage, and staleness; unsupported semantic versions/actions remain unapplied. Unknown optional descriptive fields may be ignored, never unknown safety-critical semantics. Keep database, API, taxonomy, and export-format versions distinct. Replace the current best-effort ALTER—whose error is discarded—with explicit ordered, transactional migrations and refusal to write a newer unsupported schema: server/internal/store/store.go:91-122. Preserve original rows and provenance during backfill; label unverifiable legacy data rather than automatically approving it. Add idempotency keyed by authenticated principal plus client nonce: identical retries return the original result; nonce reuse with a different canonical body returns conflict. Persist the outbox until acknowledgement. For JSON numbers, enforce cross-language safe bounds or use decimal strings for larger counters; RFC8785 documents numeric interoperability constraints [S6]. Existing createdAt is Unix seconds, while spans are milliseconds—document units explicitly rather than silently changing them. Test upgrade, rollback-by-restore, interrupted import, and old-client behavior before rollout.

10. Concrete failure/correctness matrix, all PROPOSED responses unless noted. Wrong cut or ambiguous checksum → no automatic timeline binding; owner chooses playback block versus explicit unfiltered warning. Unknown duration/out-of-range span → reject or quarantine, never silently clamp. Submit timeout/retry → durable outbox and same idempotency result. Forged identity/Sybil votes → quarantine plus authenticated continuity; no automatic deletion of curated records. Duplicate delta → no additional revisions or votes. Missing/out-of-order delta → leave current view intact and fetch a complete base. Tampered/truncated/unsupported snapshot → reject before atomic swap. Old signed snapshot or same-sequence different hash → reject/quarantine using persisted history. Publisher deletion → remove its active imported assertion, retain local curation with stale-source warning. Partition or expired feed → continue last-known-good only under explicit stale-data policy; unknown content remains unknown. Crash mid-import → old or new complete view, never half a namespace. Compromised publisher → stop new acceptance after learned revocation; offline nodes cannot guarantee immediate containment. Lost live SQLite/WAL state → restore a consistent tested backup; public dumps cannot recover private policy or votes. Current provider errors return an empty segment result, which is not proof of a runtime filtering guarantee: plugin/CleanyfinSegmentProvider.cs:87-92.
