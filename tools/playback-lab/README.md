# Playback lab

First test: given a start and end timestamp, remove that interval and nothing else. From the repository root on Linux or macOS with Python 3 and Docker:

```sh
python3 tools/playback-lab/check-cut.py
```

Docker downloads a pinned Jellyfin image on first use for its bundled FFmpeg. The test containers have no network, expose no ports and mount only the test's temporary directory. No Jellyfin account, household library, AI model, or private configuration is needed. The test removes its generated media when finished; Docker retains the cached image.

The six-second synthetic movie has three distinguishable pictures and tones. The middle two seconds are marked. The test makes a lossless reference edit, decodes both files, and checks that the output equals the original prefix plus suffix, byte for byte, separately for picture and sound. A missing allowed frame, an extra marked frame, or a changed audio sample fails the check.

This is a reference for what correct output looks like, **not a Cleanyfin playback implementation**. Its timestamps align with video frames and audio samples.

## Shared hard fixture: compare playback paths

The hard kit measures leaked and missing picture and sound against the same 20-second clip. Its one cut removes source frames 137–262 (5.480 to 10.520 s, end exclusive), inside both H.264 GOPs and AAC packets. The generator writes `source.mp4`, a lossless `reference.mkv`, and Kodi and mpv edit lists derived from `plan.json` (lab format v0, **not** a product contract). From the repository root:

```sh
python3 tools/playback-lab/hard-fixture.py NEW_DIRECTORY
python3 tools/playback-lab/analyze-capture.py --plan NEW_DIRECTORY/plan.json --video CAPTURE --audio CAPTURE --json
python3 tools/playback-lab/check-kit.py
```

Supply either or both capture options; pass the same recording to both to check both tracks. `--video` also accepts a directory of numbered images in one format, in capture order. Preserve the full picture so the frame barcode stays in view. Repeated frames are reported; backward jumps in source order fail. `--audio` accepts WAV or another media file, or raw `.pcm`/`.s16le` (48 kHz mono signed 16-bit little-endian). Audio times start at the first decoded sample; the detector reports 5 ms windows with a tone amplitude of at least 0.10 full scale and tolerates up to 5 ms of loss per neighbouring tone. This is a thresholded measurement, not sample-by-sample proof. `--json` adds the machine-readable result on the last line.

Passing the self-test says nothing about any real player until that player's output is captured and analyzed.

## Authenticated cut-list handoff (disposable 10.11.11 only)

Run `python3 tools/playback-lab/check-plugin.py --case auth-range` from the repository root. Prerequisites: Docker, Python 3, the pinned Jellyfin image, `mcr.microsoft.com/dotnet/sdk:9.0` and the [desktop mpv lab image](prototypes/edit-list-players/README.md). The SDK restores build dependencies; the server and player share only a private loopback network namespace. No host port is published. The runner owns the synthetic source, hashes it and mounts that **one file** read-only. Do not substitute a mutable movie directory. On success the server and working data are removed; on failure the stopped container name and private local directory are printed. That directory includes Jellyfin's disposable authentication database; do not publish it.

The fixture-only issue endpoint is off by default. In the lab the descriptor and source have different short-lived bearer handles. Anonymous possession works until expiry or revocation; it is not proof of possession of the enrolled device. The plugin checks the viewer, device token hash, session, library rights, exact source and plan on each leg. Only Jellyfin's native static-file action sends movie bytes. At stock logging levels 10.11.11 printed the **native viewer token** at logout (`Emby.Server.Implementations.Session.SessionManager`, Information). The runner sets only that category to Warning before startup and scans server logs for all native test tokens and both capability values. HTTP logging remains at its defaults. Before considering a proxy, debug logging or another player, redact entire capability URLs (including paths), queries and auth headers at every layer. Completed reads and buffered bytes cannot be revoked.

A successful **handoff** does not certify editing fidelity. The runner prints the unchanged scorer verdict and compares stereo PCM against the trimmed unfiltered control. A kept-tone measurement can fail even when every HTTP assertion passes and no marked frames or tone are detected. No PlaybackInfo override, pointer library, device eligibility or household playback is provided by this case.

### Automatic Google TV measurement (experimental)

On this Fedora lab host, run `python3 -I tools/playback-lab/tv-harness.py --gpu host --ram-mib 1536` from the repository root. The larger 2048 MiB clone hit the session's 3 GiB memory-pressure ceiling despite ample host-wide memory; guest RAM is part of the measured device mode. `--json` prints a single machine-readable object on stdout; diagnostics go to stderr. A nonzero exit means at least one claim failed or remains unresolved. Before starting services the harness gives load, available memory and storage pressure up to three minutes to settle; budget up to 20 more minutes plus teardown. Timeouts distinguish observed host contention from a timed-out test stage on an otherwise ready host. `--keep` retains private scratch **including disposable credentials** for debugging; do not share it. The normal run deletes the cloned TV, server, media and logs, and checks that desktop audio sinks and default did not change.

Use an x86_64 Linux host with KVM, unprivileged user/network namespaces, Python 3, Docker and the plugin lab images, GitHub CLI release access, the Android SDK full emulator engine, platform-tools, `platforms/android-36`, build-tools 36.0.0, a JDK, and an installed API 36 `google-tv/x86_64` image with the `cleanyfin-tv` AVD configuration. Xvfb, xauth, xdpyinfo, PipeWire, wireplumber, pipewire-pulse, pactl, parec, nsenter, ip, ss, curl and FFmpeg must already be available. `--gpu host` requests the host OpenGL path but does not promise hardware rendering; the run prints the actual advertised adapter. On this Fedora host it selects software llvmpipe, a different tuple from SwiftShader. `--llvmpipe-threads 2` or `4` requests an emulator-only Mesa raster worker cap; the summary distinguishes the requested cap from the observed renderer. The SwiftShader alias-fix run confirmed handoff but saw only 110/500 and 114/500 uncut frames and failed its known-tone controls. Crash reporting is disabled on the clone. The harness does not install packages or accept licenses. It verifies the official Wholphin 1.1.2 x86_64 release digest and uses a separate self-instrumenting test input package: it never patches the player. The cloned guest has no route off its host's private loopback namespace. Server and player use a new synthetic viewer, Quick Connect and a run-local shelf, not an existing Jellyfin instance.

**Configuration route (Wholphin 1.1.2).** An early attempt could see Advanced Settings but could not focus it. On this fixture, wait until the *focused subtree* is in the Home drawer, then follow each D-pad move with a fresh UI dump. From Home it took 4 Down moves to Settings; from “Sign in automatically” it took 21 to Advanced Settings; from “Show Clock” it took 18 to the ExoPlayer backend value. The choice dialog opens focused on ExoPlayer; one Down selects MPV. On reopening Advanced Settings the backend value was MPV and the MPV-only editor was 21 moves from Show Clock. These are observations, not hard-coded row indexes. Dismissing the editor keyboard and reading back the **saved** multiline value are separate steps. The disposable guest is a production `user` image: the supported command returned `adbd cannot run as root in production builds`; no private files were written directly. The release manifest exposes MainActivity, but the v1.1.2 intent parser handles search, item view and play, not a settings destination. Neither root nor a guessed deep link is a fallback.

Claims require the MPV-only settings UI, rereading the saved `mpv.conf` and positive diagnostics from Wholphin's own process. `DirectPlay` alone is not proof of playback. The harness records the cloned 1280×720 display via Android's compositor at 320×180 with actual MP4 timestamps (host VP9 recorder as fallback). It records the private QEMU sink monitor as 48 kHz stereo PCM and checks the active QEMU sink. It does not use `ao=pcm` or an in-player tee. Changes to volume are limited to the private sink and guest; the guest input fallback uses volume-up keys and reads back the result. A libmpv EOF, cleared Jellyfin session or departed player surface can end a take. If none arrives, the fixture runtime at that speed plus 14 seconds caps capture; the harness still scores what it recorded.

The private byte-forwarding relay emits only bounded PlaybackInfo facts from the genuine app, including its posted backend profile, native container selection and reason header. It does not rewrite the request, forward any routes outside this disposable loopback, or persist paths, URLs, credentials or response bodies. Experimental lab enrollment matches the authenticated session device and the built DLL; the summary records a digest of the device ID, not the ID itself. The separate test input uses the clone's Android MediaSession for pause/play only, targeting the single Wholphin session. Its MPV player does not advertise MediaSession seek: the lab tries the app's D-pad seek path after reading back the native 5-second forward setting. The stop test sends the stock TV Stop key away from EOF and requires a newly persisted bookmark before reopening Wholphin to its actual Resume choice. The harness never writes Jellyfin progress.

The picture and sound controls gate their respective claims independently. `--split-capture` diagnoses recorder load: run audio and display taps on different 1× takes without changing either of the player's outputs. Each filtered assessment requires its own handoff. Each display take warms the app and starts the recorder before playback, with two seconds of pre-roll; analysis trims by barcode. Picture needs all 500 uncut frame identities in source order, including 126 marked. If 1× cannot resolve the sequence, the harness tries a **picture-only** 0.25× pass using Wholphin's playback-speed menu: its player page starts at 1× regardless of the saved `mpv.conf` speed. The harness uses D-pad focus on the stock unlabeled gear, selects `.25`, and requires the `0.25` readback. The slow pass must start on a witnessed frame zero and show the expected longer presentation; it cannot prove 1× kept frames, leak absence or stall timing. The 1× take reports sampled counts and a timing bound when both join transitions are bracketed. For the filtered item, require the actual pointer POST, EDL GET and original range GET. The picture targets are 136 then 263, all 374 kept frames and no marked presentation; any absence claim is limited by the largest measured timestamp gap. A capture gap, late screenshot or server bookmark alone cannot prove no stall or an exact first resume frame.

The harness scores two independent uncut PCM renders before scoring the cut. A fixed onset threshold anchors each capture once; the decoded file only gives the threshold's offset from sample zero. It compares the filtered prefix and suffix to their corresponding **rendered**, uncut regions without re-aligning at the splice. For each whole region and the 20 ms immediately on each side of the join, the summary records changed sample counts, extent, peak, and error energy/RMS against the two-take repeatability floor. A region whose repeatability error is as large as its reference signal cannot establish preservation. Differences do not by themselves measure how many playback samples were inserted or deleted. Both channels retain the 5 ms tone-window score (0.10 full-scale amplitude): nominal 880 Hz duration calibrates leak detection, and measured 440/660 Hz losses are compared with the uncut renders' window-count repeatability. Zero measured 880 Hz is not proof below that detection limit.

**Fixed integration gap on Jellyfin 10.11.11:** the real Wholphin 1.1.2 MPV profile advertises MOV and MP4, and native PlaybackInfo chooses `mov` and DirectPlay without a transcode URL. The earlier plugin rejected that alias, producing `NoCompatibleStream` before either GET. The old `pointer-refresh` case passed because its synthetic profile advertised `mp4` only, masking the gap. The case now verifies native selection of `mov`, both the Wholphin-shaped and MOV-only filtered requests, and a Matroska-only refusal for the same pointer. The alias change does not bypass the verified MP4 and track checks.

**Measured on the 1536 MiB llvmpipe clone, two raster workers requested:** the 1× audio and display takes and the 0.25× display take each proved the three HTTP legs. The slow uncut control showed 500/500 frames in 82.3914 s; the slow filtered take showed 374/374 kept frames in 62.2652 s, in order with 136→263. Zero marked frames were seen, but a 2480.08 ms capture gap prevents an absence claim. At 1×, the uncut display missed frames 4 and 9 and the filtered display missed frame 4; the join timing bound crossed the 40 ms stall threshold. Both uncut PCM takes detected 5025/5025 ms of the required 5040 ms mark, outside the calibration tolerance. The filtered 70/70 ms detection does not establish a marked-tone leak. The kept-tone check found 90/90 ms of 660 Hz loss against 10/10 ms repeatability; all 960 stereo frames in the 20 ms before the join changed against zero uncut differences. The 20 ms after the join lacked a useful floor (9246.58 LSB RMS error, above the reference signal). D-pad setup did not reach the navigation drawer in the seek test. Stop cleared the session but did not produce a new bookmark. No eligibility was recorded.

Only small `summary.json` and optional experimental `candidate.json` are written under `delivery/evidence/runs/`. Failed handoffs, mixed-speed summaries and split-capture diagnostics do not yield a 1× candidate. A candidate with unverified settings describes the **attempted** tuple, not an observed backend. It is never automatically installed. Before changing a reviewed register, match every tuple field (including both builds and device mode), require controls and handoff receipts, review detection limits and validate against `delivery/schema/evidence-register-v1.schema.json`. Nothing here measures HDMI, a physical TV, other players or Jellyfin 12.4.

### One-pointer falsifier

Run `python3 tools/playback-lab/check-plugin.py --case pointer-refresh` with the same prerequisites. It creates **one** plugin-owned inert pointer, refreshes only disposable fixture folders/items, and compares the ordinary original's response bytes (apart from the fresh play-session nonce) with the flag off. The simulated Wholphin POST exercises native 10.11.11 negotiation on the original, not a probe or client impersonation at the media URL. A real server ffprobe must receive 410. The desktop control and cut use the unchanged frame/tone scorer. A successful grant, refresh and restart test is not an Android presentation measurement or a client-support claim.

On the Android 16 `cleanyfin-test` emulator, unmodified Wholphin 1.1.2/MPV chose DirectPlay on plugin build `6222440e0ee3f0f3be5e57108da07834f46b909f05508ca7ab5f487c43646f95`: pointer POST 200 → list GET 200 → native original range 206. The original control showed 65 marked presentations. The straight cut showed zero marked and 193 distinct kept frames at 15.4 fps; 35 screencaps at 1.85 Hz contained no red. Five-second seek controls showed source frames 71 → 301 → 0. Withheld projection, original ACL denial and flag-off each returned `NoCompatibleStream`. A 3 s grant did not recall buffered bytes; replay made a new POST. After a server restart the same handoff succeeded but every recorded frame was unreadable. Wholphin then timed out loading the shelf in Exo mode; no real Exo playback or plugin-absent trial was completed. No TV sound, frame-complete join or physical hardware evidence.

### Per-viewer shelf lifecycle

Run `python3 tools/playback-lab/check-plugin.py --case shelf-isolation`. Two independent policies over the **same original** omit either `[137,263)` or `[137,200)` source frames. The latter oracle deliberately scores picture only: its retained interval contains some of the 880 Hz tone, so the first cut's audio oracle would be false for it. The scorer is unchanged. The native progress, stop, watched, browse and restart assertions use filtered item IDs, not source-time conversion. The runner exercises both a default all-folders account and explicit folder lists; neither changes enrollment. It checks same-size replacement with the same duration, inspection for grants/media output, and byte-identical originals after cleanup. See the [operator input layout and limits](../../plugin/README.md#per-viewer-playback-shelves-disposable-101111-lab-only). No new client or household support is claimed.

## Browser playback: original vs. filtered timeline

Run `python3 tools/playback-lab/serve-web.py`, open the printed loopback URL in Chromium, and choose **Run playback checks**. This generates a temporary compressed clip, a packaging index and an exact-source cut plan. The command serves only that temporary lab until Ctrl-C. There is no household library scan, edited movie on disk, or AI dependency.

The original control must show the red scene and its tone. The experimental player omits its entire encoded fragment from the browser's media buffer, preserves the blue and green sections and their tones, and maps a seek into the omitted scene to the start of green. The checks report sampled colors, dominant tones, duration and seek landing. They are **not** a proof of zero audio samples or compatibility with stock Jellyfin Web. Unsupported codecs, a wrong source, and unaligned timestamps must not quietly switch to unfiltered playback.

For an integration check in a **disposable loopback Jellyfin 10.11.11 lab only**: generate the bundle with `web-fixture.py NEW_DIRECTORY`; index its `Fixture.mp4` in the synthetic test library; put the generated HTML, JS and JSON assets under a separate lab path in the container web root. Load the page with `?item=<fixture item ID>`. It uses the passwordless, non-admin lab user `Viewer` to fetch the original through Jellyfin's direct stream endpoint. Do not configure an existing household server this way. This is a separate client, not a change to the stock player. See the [client evidence and constraints](../../knowledge-base/01-working/long-term-architecture-2026-10-07/10-client-boundary-and-browser-proof.md).
